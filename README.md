# ネットワークエンジニア・シミュレーター v5.0（Phase 1）

ネットワークエンジニアとして働くシミュレーションゲーム。スマートフォン（iPhone縦画面）優先の
UIで、「依頼を受け、現場を調べ、設計し、機器を購入し、物理配線し、設定し、通信試験し、
障害を調査・修理し、納品する」という一連の仕事の流れを遊べます。

- v1.0：機器を買って配置してケーブルでつなぎ、通信テストするコアループ
- v2.0：ゲーム都合の接続制限を撤廃し、IPアドレス・サブネット・DHCP・NAT・DNSなど
  現実のネットワークの仕組みを導入
- v3.0：ネットワーク構成図ではなく「建物の平面図」をゲーム画面の中心に据え、
  部屋・LANコンセント・パッチパネルを使った物理配線、ケーブルの長さ/切断、電源障害を追加
- v4.0：「ネットワークを作るパズル」から「ネットワークエンジニアとして働く」体験へ。
  依頼（案件）を顧客からの手紙として提示し、現場調査（インスペクト）モードと
  説明ブックを追加
- v5.0（Phase 1）：「どの機器を、なぜ選ぶか」という機器選定の奥行きを追加。
  1種類だった「PC」を、デスクトップPC・ノートPC・ワークステーションの3種類に
  作り分け、ショップにカテゴリ別の一覧と機器比較UIを追加

## 遊び方

案件は9件用意されており、達成すると報酬を得て次の案件に進みます
（同じネットワーク・同じ建物を継続して拡張していく形式です）。

ヘッダーの依頼名をタップすると📩依頼内容（顧客名・要件・納期・予算目安）を確認できます。
案件完了画面では、報酬に加えて通信成功率・施工コストと予算の対比・配線距離・配線ミス件数・
顧客要求の達成チェックを表示します。

1. **案件01** — ONU・ルーターを使い、1台のPCをインターネットに接続する
2. **案件02** — 5台のPCを接続する（ルーターのLANポートだけでは足りず、スイッチが必要）
3. **案件03** — PCのIPアドレスを手動設定し、正しく通信できるようにする
4. **案件04** — 突然壊れたPC（ゲートウェイ設定が消える）を診断・復旧する
5. **案件05** — 社内サーバーを設置し、固定IPで正しく接続する
6. **案件06** — 部屋のLANコンセントにPCをつなぎ、パッチパネル経由でスイッチへ配線する
7. **案件07** — 離れた倉庫にPCを設置する（直線配線では100mの上限を超えるため、
   中継スイッチ／パッチパネルを間に設置する必要がある）
8. **案件08** — 会議室にWi-Fiアクセスポイントを設置し、無線で通信できるようにする
9. **案件09** — 設計部にワークステーションを導入する（通常のPCではなく、
   ワークステーションであることが要件）

「🔍調査」モードでPCやサーバーを選ぶと、物理接続 → 電源 → ケーブル長 → ポート状態 → IP →
サブネット → ゲートウェイ → ルーティング → NAT → DNS → インターネット到達、の
11段階を順番にチェックし、最初に失敗した段階とその理由を表示します（Pingツールも使えます）。
PC・サーバー以外の機器（スイッチ・ルーター・LANコンセントなど）を選ぶと、現場調査として
設置場所・電源状態・各ポートの接続先とケーブル情報を確認できます。
答えを一度に全部見せず、「なぜ繋がらないのか」を自分で突き止めるゲーム体験を狙っています。

「🔌配線」モードでは機器同士をタップしてケーブルを引けるほか、既存のケーブルをタップすると
切断できます。

ヘッダーの📖ボタンから、いつでも説明ブックを開けます。ネットワーク基礎・機器・配線・
ネットワーク設定・トラブル対応のカテゴリごとに、「①これは何？②現実では？③ゲームでは？
④構成例」の4項目で解説しています。多くのページには「🔧この画面で試してみる」ボタンがあり、
タップすると該当の操作モードにすぐ切り替わります。

## セットアップ


## 技術構成

- Vite + TypeScript（フレームワークなしのシンプル構成）
- 機器・ポート・接続・部屋・案件・説明ブックはすべてデータとして管理
  （`src/devices.ts`, `src/rooms.ts`, `src/missions.ts`, `src/book.ts`, `src/types.ts`）
  しているため、将来の機器追加・案件追加・複数拠点などの拡張がしやすい構造になっています。
- `src/rules.ts` … 物理層の接続可否（有線ポート同士／無線ポート同士のみ）を判定
- `src/netutils.ts` … IPアドレス計算、L2ドメイン（ルーターを越えないLAN範囲）の特定、
  DHCPアドレスの割り当て、IP重複検出、最短経路探索
- `src/cables.ts` … ケーブル長の計算（マップ座標からメートル換算）と上限判定
- `src/diagnostics.ts` … 11段階の通信診断エンジンとPing機能
- `src/book.ts` … 説明ブックのカテゴリ・ページ内容

## 実装済み機能（v5.0 Phase 1）

- ショップでの機器購入・所持金管理（デスクトップPC・ノートPC・ワークステーション・
  サーバー・ルーター・スイッチ・ONU・Wi-Fi AP・LANコンセント・パッチパネル・通信ラック）。
  ショップはコンピューター／サーバー／ネットワーク機器／配線・什器のカテゴリ別に表示
- 機器比較UI：ショップで2件以上の機器に「比較」チェックを入れると、価格・ポート・
  スペック（CPU/メモリ/用途など）を並べた比較テーブルを表示できる
- 建物の平面図（部屋）の表示、機器の配置・移動（ケーブルは追従）
- 配線モードでの機器同士の接続（ゲーム都合の制限なし）と、ケーブルをタップしての切断
- ケーブルの種類・長さ（マップ座標から実距離換算）・上限超過の判定
- ⚙設定画面：ルーターのLAN IP/サブネット/DHCP範囲/NAT、PC・サーバーのDHCP/固定IP設定、
  ルーター・スイッチ・ONU・APの電源ON/OFF、機器ごとの各ポートON/OFF（ポート障害の再現）
- 🔍調査モード：PC・サーバーは11段階の通信診断＋Pingツール、それ以外の機器は現場調査
  （設置場所・電源・ポートごとの接続先とケーブル情報）
- 📩依頼内容モーダル：顧客名・要件・納期・予算目安を表示
- 📖説明ブック：基礎・機器・配線・設定・トラブル対応のカテゴリ別ページと練習モードへの導線
- 通信テスト・案件進行・報酬・完了画面（通信成功率・施工コストと予算の対比・配線距離・
  配線ミス件数・顧客要求の達成チェックを表示）
- 案件04での自動障害発生（ゲートウェイ設定の消失）と復旧確認
- ゲームリセット

## v3.0の完成状況

設計書v3の完成チェックリスト（§33）のうち、通信ラックの配置と物理障害（電源・ケーブル長・
ポート障害）の再現を含め、ほぼすべての項目に対応しました。唯一、通信ラックはあくまで通信室に
置く装飾的な什器で、ラックの高さ（U数）でどの機器が収まるかを管理する機能は設計書自身が
将来バージョンに委ねている項目のため、今回も見送っています。

## v4.0の完成状況

設計書v4のPhase1〜6（案件基盤・現場調査・配線ミス記録・IP/DHCP/DNS設定・通信試験/診断・
説明ブック）はすべて対応済みです。§25の最初の完成目標（PC×5・Wi-Fi AP・LANジャック×5・
パッチパネル・インターネット接続）は、案件02（5台のPC接続）・案件06（LANコンセント配線）・
案件08（Wi-Fi）の組み合わせで一通り体験できる構成にしています。

§10で購入候補として挙げられているL2/L3スイッチの区別・UPS・LANテスターは、あえて追加して
いません。L3スイッチはVLAN/サブネット間ルーティングなど今回まだ実装していない機能があって
初めて意味を持つため、今の仕組みのままではL2スイッチと同じ挙動の割高な機器になってしまいます。
UPSも「瞬断」のようなランダム障害イベントが無いと効果を発揮できません。LANテスターも、
🔍調査モードのポート情報表示がすでに同じ役割を果たしています。実体の伴わない見た目だけの
購入品を増やすより、これらは対応する仕組み（VLAN/ランダム障害など）と一緒に実装する方が
一貫性があると判断しました。

## v5.0（Phase 1）の完成状況

設計書v5の§30は「一度に全部作らない。まずカテゴリ→種類の仕組みを作り、
コンピューター系3種類→ネットワーク機器の順に」と明記しているため、今回はその第一段階に
絞りました。対応したのは、機器をカテゴリ（コンピューター／サーバー／ネットワーク機器／
配線・什器）で管理する仕組み、その最初の適用例としてのデスクトップPC・ノートPC・
ワークステーションの作り分け（接続手段・価格・スペックがそれぞれ異なる）、ショップでの
カテゴリ別表示と機器比較UI、機器選択そのものを要件にした案件09です。

§30が次段階として挙げているルーター・L2スイッチ・PoEスイッチ・Wi-Fi APの「種類」分け
（用途・価格帯違いのバリエーション）は、今回はまだ追加していません。現状の仕組みのままでは
既存のルーター・スイッチ・APと機能面で区別がつかない、価格だけ違う機器になってしまうため、
PoE給電の仕組みなど§30が想定する「違いを生む仕組み」と合わせて実装する方が一貫性があると
判断しました（v4.0でL2/L3スイッチ・UPS・LANテスターを見送った際と同じ考え方です）。

## v5以降でまだ実装しないもの

設計書v5が挙げるPoE給電システム、セキュリティ機器（ファイアウォール専用機・UTM等）、
オフィス什器（プリンター・複合機等）、サーバー/ストレージ機器の細分化、機器ごとの
カスタムアイコン・状態変化（電源off/障害時の見た目変化）、ルーター・スイッチ・APの
用途別バリエーション（上記の理由によりPoEなど対応する仕組みと合わせて実装予定）は、
§30の指示どおり段階的に追加する予定です。

案件ごとの独立した予算上限・複数の現場（建物）の選択・キャリアレベル進行、説明ブックからの
独立した練習用サンドバックス画面、壁沿いの配線経路（直線表示のみ）、通信ラックのU単位管理、
複数フロア、Wi-Fiの電波範囲表示、マップのピンチズーム、ネットワーク構成図表示への切替、
ランダム障害の自動発生、VLAN、STP、OSPF/BGP、IPv6、ACL、詳細なFirewall設定、VPN、
詳細なポートフォワーディング、TCP/UDPの詳細、ARP、MACアドレス管理、パケットキャプチャ、
本格的なルーティングプロトコル、L2/L3スイッチの区別・UPS・LANテスター（対応する仕組みと
合わせて実装予定）は将来バージョンで追加予定です。
