# ネットワークエンジニア・シミュレーター v6.0（VLAN Phase 1-3）

ネットワークエンジニアとして働くシミュレーションゲーム。スマートフォン（iPhone縦画面）優先の
UIで、「依頼を受け、現場を調べ、設計し、機器を購入し、物理配線し、設定し、通信試験し、
障害を調査・修理し、納品する」という一連の仕事の流れを遊べます。

- v1.0：機器を買って配置してケーブルでつなぎ、通信テストするコアループ
- v2.0：ゲーム都合の接続制限を撤廃し、IPアドレス・サブネット・DHCP・NAT・DNSなど
  現実のネットワークの仕組みを導入
- v3.0：ネットワーク構成図ではなく「建物の平面図」をゲーム画面の中心に据え、
  部屋・LANコンセント・パッチパネルを使った物理配線、ケーブルの長さ/切断、電源障害を追加
- v4.0：「ネットワークを作るパズル」から「ネットワークエンジニアとして働く」体験へ。
  依頼（案件）を顧客からの手紙として提示し、現場調査（インスペクト）モードと
  説明ブックを追加
- v5.0（Phase 1）：「どの機器を、なぜ選ぶか」という機器選定の奥行きを追加。
  1種類だった「PC」を、デスクトップPC・ノートPC・ワークステーションの3種類に
  作り分け、ショップにカテゴリ別の一覧と機器比較UIを追加
- v5.0（機器UI刷新）：絵文字だったゲーム内の機器アイコンを専用SVGアイコンに統一し、
  独立した「比較」機能を廃止して「情報」に統合。購入前の機器だけでなく設置済みの
  機器もタップして情報（機器仕様と現在の状態を分離して表示）を確認できるように変更
- v6.0（VLAN Phase 1-3）：「選んだ機器を、どのようなネットワークにするか」を
  プレイヤー自身が設計するフェーズへ。同じスイッチに複数の部署を収容しつつVLANで
  論理的に分離できるようにし、アクセスポート／トランクポートの設定と、VLANの
  不一致を切り分ける専用の診断ステップを追加

## 遊び方

案件は10件用意されており、達成すると報酬を得て次の案件に進みます
（同じネットワーク・同じ建物を継続して拡張していく形式です）。

ヘッダーの依頼名をタップすると📩依頼内容（顧客名・要件・納期・予算目安）を確認できます。
案件完了画面では、報酬に加えて通信成功率・施工コストと予算の対比・配線距離・配線ミス件数・
顧客要求の達成チェックを表示します。

1. **案件01** — ONU・ルーターを使い、1台のPCをインターネットに接続する
2. **案件02** — 5台のPCを接続する（ルーターのLANポートだけでは足りず、スイッチが必要）
3. **案件03** — PCのIPアドレスを手動設定し、正しく通信できるようにする
4. **案件04** — 突然壊れたPC（ゲートウェイ設定が消える）を診断・復旧する
5. **案件05** — 社内サーバーを設置し、固定IPで正しく接続する
6. **案件06** — 部屋のLANコンセントにPCをつなぎ、パッチパネル経由でスイッチへ配線する
7. **案件07** — 離れた倉庫にPCを設置する（直線配線では100mの上限を超えるため、
   中継スイッチ／パッチパネルを間に設置する必要がある）
8. **案件08** — 会議室にWi-Fiアクセスポイントを設置し、無線で通信できるようにする
9. **案件09** — 設計部にワークステーションを導入する（通常のPCではなく、
   ワークステーションであることが要件）
10. **案件10** — 1台のスイッチに営業部・開発部を収容しつつ、VLANで部署ごとに
    ネットワークを分離する（同じVLAN内は通信でき、別VLANとは通信できない状態を作る）

「🔍調査」モードでPCやサーバーを選ぶと、物理接続 → 電源 → ケーブル長 → ポート状態 → VLAN →
IP → サブネット → ゲートウェイ → ルーティング → NAT → DNS → インターネット到達、の
12段階を順番にチェックし、最初に失敗した段階とその理由を表示します（Pingツールも使えます）。
PC・サーバー以外の機器（スイッチ・ルーター・LANコンセントなど）を選ぶと、現場調査として
設置場所・電源状態・各ポートの接続先とケーブル情報を確認できます。
答えを一度に全部見せず、「なぜ繋がらないのか」を自分で突き止めるゲーム体験を狙っています。

「🔌配線」モードでは機器同士をタップしてケーブルを引けるほか、既存のケーブルをタップすると
切断できます。

スイッチの⚙設定画面では、VLANの登録（ID・名前）と、ポートごとのVLAN設定ができます。
各ポートはAccess（1つのVLANだけに所属）かTrunk（複数のVLANを1本のケーブルで通す）を
選べます。ポートのVLAN設定を間違えると、配線もポートも正常なのに特定の機器同士だけ
通信できない、という状態を作れます（🔍調査の診断で「VLAN」の段階が失敗として表示され、
原因を切り分けられます）。ルーター自体は今回まだVLANをまたいだルーティング（V6設計書の
L3スイッチ）に対応していないため、ルーターが接続されているVLAN以外はインターネットに
出られません。

機器の情報はどこからでも確認できます。ショップの各機器の「情報」ボタン、未配置の機器
（インベントリ）の情報ボタン、地図に置いた機器のタップ（または機器右上の小さな「i」ボタン）
のいずれからも、同じ「機器仕様」（価格・ポート・CPU/メモリなど、購入後も変わらないスペック）
を確認できます。設置済みの機器では、それに加えて「現在の状態」（電源・配線・IPアドレス・
通信状態など、今どうなっているか）も分けて表示されます。情報画面の「他の機器と比較」から、
複数の機種を選んで価格やスペックを横に並べて比較することもできます（ゲーム側からおすすめは
提示しません）。

ヘッダーの📖ボタンから、いつでも説明ブックを開けます。ネットワーク基礎・機器・配線・
ネットワーク設定・トラブル対応のカテゴリごとに、「①これは何？②現実では？③ゲームでは？
④構成例」の4項目で解説しています。多くのページには「🔧この画面で試してみる」ボタンがあり、
タップすると該当の操作モードにすぐ切り替わります。

## 技術構成

- Vite + TypeScript（フレームワークなしのシンプル構成）
- 機器・ポート・接続・部屋・案件・説明ブックはすべてデータとして管理
  （`src/devices.ts`, `src/rooms.ts`, `src/missions.ts`, `src/book.ts`, `src/types.ts`）
  しているため、将来の機器追加・案件追加・複数拠点などの拡張がしやすい構造になっています。
- `src/rules.ts` … 物理層の接続可否（有線ポート同士／無線ポート同士のみ）を判定
- `src/netutils.ts` … IPアドレス計算、L2ドメイン（ルーターを越えないLAN範囲）の特定、
  VLANを考慮したポート単位の到達性判定（`findVlanDomain`）、DHCPアドレスの割り当て、
  IP重複検出、最短経路探索
- `src/cables.ts` … ケーブル長の計算（マップ座標からメートル換算）と上限判定
- `src/diagnostics.ts` … 12段階の通信診断エンジンとPing機能
- `src/book.ts` … 説明ブックのカテゴリ・ページ内容
- `src/icons.ts` … 機器種別ごとの専用SVGアイコン（絵文字は不使用）

## 実装済み機能（v6.0 VLAN Phase 1-3）

- VLAN：VLANの登録（ID・名前、既定でVLAN 1「default」が存在）、スイッチのポートごとの
  Access（1 VLANに所属）／Trunk（複数VLANを通す）設定
- VLANを考慮したL2到達性判定：ポート単位でVLANの一致を確認しながら経路を辿るため、
  Access/Trunkの設定を間違えると、配線・ポートは正常なのに特定の機器同士だけ
  通信できない状態を再現できる（DHCP割り当て・IP重複検出もVLANの範囲内で行う）
- 🔍調査の12段階診断に「VLAN」を追加（物理接続・電源・ケーブル長・ポート状態の次、
  IP設定より前）。物理的な配線の問題とVLAN設定の問題を切り分けて診断できる

- ショップでの機器購入・所持金管理（デスクトップPC・ノートPC・ワークステーション・
  サーバー・ルーター・スイッチ・ONU・Wi-Fi AP・LANコンセント・パッチパネル・通信ラック）。
  ショップはコンピューター／サーバー／ネットワーク機器／配線・什器のカテゴリ別に表示
- 機器アイコンはすべて専用のモノラインSVGアイコン（`src/icons.ts`）。ショップ・
  インベントリ・地図上の表示すべてで共通の1つのアイコンセットを使用（絵文字は不使用）
- 「情報」画面：ショップの機器・未配置の機器・地図に設置済みの機器のいずれからも、
  同じ機器データ（`DeviceCatalogItem.specifications`）から生成される「機器仕様」を
  確認できる。設置済みの機器では、さらに実際のゲーム状態から計算した「現在の状態」
  （電源・配線・IPアドレス・通信状態など）を分けて表示する
- 機器比較：「情報」画面の「他の機器と比較」から、比較したい機種を選んで価格・ポート・
  スペックを横に並べたテーブルで見比べられる（独立した「比較」機能は廃止し、情報画面の
  補助機能として統合）
- 建物の平面図（部屋）の表示、機器の配置・移動（ケーブルは追従）
- 配線モードでの機器同士の接続（ゲーム都合の制限なし）と、ケーブルをタップしての切断
- ケーブルの種類・長さ（マップ座標から実距離換算）・上限超過の判定
- ⚙設定画面：ルーターのLAN IP/サブネット/DHCP範囲/NAT、PC・サーバーのDHCP/固定IP設定、
  ルーター・スイッチ・ONU・APの電源ON/OFF、機器ごとの各ポートON/OFF（ポート障害の再現）
- 🔍調査モード：PC・サーバーは11段階の通信診断＋Pingツール、それ以外の機器は現場調査
  （設置場所・電源・ポートごとの接続先とケーブル情報）
- 📩依頼内容モーダル：顧客名・要件・納期・予算目安を表示
- 📖説明ブック：基礎・機器・配線・設定・トラブル対応のカテゴリ別ページと練習モードへの導線
- 通信テスト・案件進行・報酬・完了画面（通信成功率・施工コストと予算の対比・配線距離・
  配線ミス件数・顧客要求の達成チェックを表示）
- 案件04での自動障害発生（ゲートウェイ設定の消失）と復旧確認
- ゲームリセット

## v4.0の完成状況

設計書v4のPhase1〜6（案件基盤・現場調査・配線ミス記録・IP/DHCP/DNS設定・通信試験/診断・
説明ブック）はすべて対応済みです。§25の最初の完成目標（PC×5・Wi-Fi AP・LANジャック×5・
パッチパネル・インターネット接続）は、案件02（5台のPC接続）・案件06（LANコンセント配線）・
案件08（Wi-Fi）の組み合わせで一通り体験できる構成にしています。

§10で購入候補として挙げられているL2/L3スイッチの区別・UPS・LANテスターは、あえて追加して
いません。L3スイッチはVLAN/サブネット間ルーティングなど今回まだ実装していない機能があって
初めて意味を持つため、今の仕組みのままではL2スイッチと同じ挙動の割高な機器になってしまいます。
UPSも「瞬断」のようなランダム障害イベントが無いと効果を発揮できません。LANテスターも、
🔍調査モードのポート情報表示がすでに同じ役割を果たしています。実体の伴わない見た目だけの
購入品を増やすより、これらは対応する仕組み（VLAN/ランダム障害など）と一緒に実装する方が
一貫性があると判断しました。

## v5.0（Phase 1）の完成状況

設計書v5の§30は「一度に全部作らない。まずカテゴリ→種類の仕組みを作り、
コンピューター系3種類→ネットワーク機器の順に」と明記しているため、今回はその第一段階に
絞りました。対応したのは、機器をカテゴリ（コンピューター／サーバー／ネットワーク機器／
配線・什器）で管理する仕組み、その最初の適用例としてのデスクトップPC・ノートPC・
ワークステーションの作り分け（接続手段・価格・スペックがそれぞれ異なる）、ショップでの
カテゴリ別表示と機器比較UI、機器選択そのものを要件にした案件09です。

§30が次段階として挙げているルーター・L2スイッチ・PoEスイッチ・Wi-Fi APの「種類」分け
（用途・価格帯違いのバリエーション）は、今回はまだ追加していません。現状の仕組みのままでは
既存のルーター・スイッチ・APと機能面で区別がつかない、価格だけ違う機器になってしまうため、
PoE給電の仕組みなど§30が想定する「違いを生む仕組み」と合わせて実装する方が一貫性があると
判断しました（v4.0でL2/L3スイッチ・UPS・LANテスターを見送った際と同じ考え方です）。

機器UI修正指示書の5つの目的（§1）のうち、絵文字アイコンの廃止、独立した「比較」機能の

機器・インベントリの機器・地図上の機器のいずれからも開け、`DeviceCatalogItem`
（`specifications`）を唯一のデータソースとして共有しているため、今後カテゴリや機種が
増えても、機器データさえ追加すれば情報画面は自動的に対応できる構造になっています。

指示書§16が挙げる新規機種（タブレット・L2/L3/PoEスイッチ・業務用ルーター・プリンター・
複合機・IP電話・防犯カメラ・NAS・タワー/ラックサーバー等）の追加は、今回のスコープに
含めていません。今回の目的はあくまで「情報の見せ方」の仕組みを整理することで、指示書
自身も§18で「機器を増やす前に、まず機器データと情報表示の仕組みを整理する」としている
ため、その仕組み作りを優先しました。同じ理由で、情報画面の「設定・移動・撤去」のうち
「撤去」（設置済み機器の削除・売却）も見送っています。撤去には返金の有無など未確定の
ゲームデザイン上の判断が必要で、今回の指示書が求める5つの目的にも含まれていないため、
中途半端な実装を避けました。「設定」ショートカットボタンは実装しています。

## v6.0（VLAN Phase 1-3）の完成状況

設計書v6の§34開発順序は、Phase1「VLANデータ構造」→Phase2「スイッチポートのVLAN設定」→
Phase3「Trunk」→Phase4「L3スイッチ」→Phase5「VLAN間ルーティング」…と続きます。今回は
Phase1〜3、およびそれをプレイアブルにするために最低限必要な診断ステップの拡張に絞りました。

VLANはポート単位のAccess/Trunk設定として実装し、既存の全機器・全案件がそのまま動くよう、
スイッチの各ポートは新規購入時に自動でVLAN 1（default・Access）へ設定されます。VLANを
またいだ通信が「できない」ことをプレイヤーが確認できるよう、ルーターは今回あえて特定の
VLANの一員として扱うだけにとどめ（VLANをまたぐルーティングは行わない）、L3スイッチが
実装されるPhase4まではVLANの分離だけを体験する設計にしています。これは設計書v6自身が
Phase4より前にVLAN単体を置いている構成と一致します。

L2/L3スイッチの区別は、v4.0で「区別を導入してもVLAN/ルーティングの仕組みが無ければ
同じ挙動の割高な機器になる」という理由で見送っていましたが、VLANが実装された今もまだ
導入していません。理由は、設計書v6の§7-§9が示すとおりL2/L3の実質的な違いは
「VLAN間ルーティングができるかどうか」（Phase4-5）にあり、ルーティング機能を伴わない
段階でL3スイッチを追加しても、これまでのスイッチと見た目以外の違いがない機器に
なってしまうためです。同じ考え方で、PoEスイッチ・ACL・Firewallも見送っています。

## v6以降でまだ実装しないもの

設計書v6が優先順位として挙げるL3スイッチ・VLAN間ルーティング・デフォルトゲートウェイの
VLANごとの設定、VLANごとのDHCPスコープ、DNSの高度化（名前解決の障害診断）、ACL、
ファイアウォール、Wi-Fi高度化（複数SSID・VLANとの連携）、論理ネットワーク設計画面、
高度な障害診断（Traceroute・nslookup等）は、§34の開発順序どおりPhase4以降で段階的に
追加する予定です。

設計書v5が挙げるPoE給電システム、セキュリティ機器（ファイアウォール専用機・UTM等）、
オフィス什器（プリンター・複合機等）、サーバー/ストレージ機器の細分化、タブレット、
ルーター・スイッチ・APの用途別バリエーション、設置済み機器の「撤去」機能も、対応する
仕組み（PoE・L3ルーティング等）と合わせて実装予定です。

案件ごとの独立した予算上限・複数の現場（建物）の選択・キャリアレベル進行、説明ブックからの
独立した練習用サンドバックス画面、壁沿いの配線経路（直線表示のみ）、通信ラックのU単位管理、
複数フロア、Wi-Fiの電波範囲表示、マップのピンチズーム、ネットワーク構成図表示への切替、
ランダム障害の自動発生、STP、OSPF/BGP、IPv6、VPN、詳細なポートフォワーディング、
TCP/UDPの詳細、ARP、MACアドレス管理、パケットキャプチャ、本格的なルーティング
プロトコルは将来バージョンで追加予定です。
