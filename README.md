# ネットワークエンジニア・シミュレーター v8.2（建物外形・壁プレビュー）

ネットワークエンジニアとして働くシミュレーションゲーム。スマートフォン（iPhone縦画面）優先の
UIで、「依頼を受け、現場を調べ、設計し、機器を購入し、物理配線し、設定し、通信試験し、
障害を調査・修理し、納品する」という一連の仕事の流れを遊べます。

- v1.0：機器を買って配置してケーブルでつなぎ、通信テストするコアループ
- v2.0：ゲーム都合の接続制限を撤廃し、IPアドレス・サブネット・DHCP・NAT・DNSなど
  現実のネットワークの仕組みを導入
- v3.0：ネットワーク構成図ではなく「建物の平面図」をゲーム画面の中心に据え、
  部屋・LANコンセント・パッチパネルを使った物理配線、ケーブルの長さ/切断、電源障害を追加
- v4.0：「ネットワークを作るパズル」から「ネットワークエンジニアとして働く」体験へ。
  依頼（案件）を顧客からの手紙として提示し、現場調査（インスペクト）モードと
  説明ブックを追加
- v5.0（Phase 1）：「どの機器を、なぜ選ぶか」という機器選定の奥行きを追加。
  1種類だった「PC」を、デスクトップPC・ノートPC・ワークステーションの3種類に
  作り分け、ショップにカテゴリ別の一覧と機器比較UIを追加
- v5.0（機器UI刷新）：絵文字だったゲーム内の機器アイコンを専用SVGアイコンに統一し、
  独立した「比較」機能を廃止して「情報」に統合。購入前の機器だけでなく設置済みの
  機器もタップして情報（機器仕様と現在の状態を分離して表示）を確認できるように変更
- v6.0（VLAN Phase 1-3）：「選んだ機器を、どのようなネットワークにするか」を
  プレイヤー自身が設計するフェーズへ。同じスイッチに複数の部署を収容しつつVLANで
  論理的に分離できるようにし、アクセスポート／トランクポートの設定と、VLANの
  不一致を切り分ける専用の診断ステップを追加
- v6.1（ひとり情シス・ヘルプデスク）：「ネットワークを作る」ゲームから「作った
  ネットワークを、たった一人の情シスとして運用する」体験へ。実在の社員から
  ヘルプデスクにチケットが届き、実際に壊れた機器を🔍調査で突き止めて直し、
  チケットを対応完了にすると報酬を受け取れる、という運用ループを追加
- v7.0（建物とWi-Fi）：「建物は背景ではない」。オフィスの部屋を拡張し、各部屋の壁の
  材質（石膏ボード・木製壁・ガラス・コンクリート・厚いコンクリート）を持たせ、
  Wi-Fiの電波強度がAPとの距離だけでなく、通過する壁の材質でも変わるようにした
- v7.1（村役場テーマ）：舞台を一般的な会社（あおぞら商事株式会社）から、実在感のある
  ○○村役場（本庁舎・別館の2施設）へ全面リニューアル。部屋・社員・案件の依頼主を
  役場の部署名（財政課・住民課・健康福祉課・建設課・総務課など）に置き換え、
  廊下・防災無線室・商工会の3部屋を追加。部屋に床材（カーペット・タイル・OAフロア・
  耐水床）を持たせ、壁の材質・床材に応じた見た目の違い（枠線の太さ/種類・床の
  テクスチャ）を追加した
- v8.0（L3スイッチ）：VLANで分離されたままだった部署同士を、実際にルーティングできる
  ようにする段階へ。VLANごとにルーティングインターフェース（SVI）を持てるL3スイッチを
  追加し、ルーターの物理ポートを部署の数だけ増やさなくても、複数のVLANがそれぞれ
  独立してインターネットに接続できるようにした
- v8.1（建物外形プレビュー・Phase 1）：ユーザー提供の実際の村役場の間取り図をもとに、
  マップを一から作り直す取り組みの最初の一歩。本庁舎（1F/2F）・別館の外形を、間取り図を
  ベクター化したSVGデータから直接抽出し、ヘッダーの🏛から確認できるプレビュー画面を
  追加した。壁・部屋・ドア・窓・家具・既存のゲームシステムへの反映はまだで、外形の形が
  合っているかを確認するためだけの下書き段階
- v8.2（建物の壁プレビュー・Phase 2）：同じベクターデータから、各部屋を構成する壁の
  部分パスをすべて抽出し、Phase 1の外形に重ねて表示するようにした。太さのある二重線と
  して壁が描かれ、階段・扉の開閉線など図面の詳細もそのまま見える。部屋・ドア・窓・家具・
  既存のゲームシステムへの反映は引き続き未着手

## 遊び方

案件は12件用意されており、達成すると報酬を得て次の案件に進みます
（同じネットワーク・同じ建物を継続して拡張していく形式です）。

ヘッダーの依頼名をタップすると📩依頼内容（顧客名・要件・納期・予算目安）を確認できます。
案件完了画面では、報酬に加えて通信成功率・施工コストと予算の対比・配線距離・配線ミス件数・
顧客要求の達成チェックを表示します。

1. **案件01** — ONU・ルーターを使い、1台のPCをインターネットに接続する
2. **案件02** — 5台のPCを接続する（ルーターのLANポートだけでは足りず、スイッチが必要）
3. **案件03** — PCのIPアドレスを手動設定し、正しく通信できるようにする
4. **案件04** — 突然壊れたPC（ゲートウェイ設定が消える）を診断・復旧する
5. **案件05** — 社内サーバーを設置し、固定IPで正しく接続する
6. **案件06** — 部屋のLANコンセントにPCをつなぎ、パッチパネル経由でスイッチへ配線する
7. **案件07** — 離れた倉庫にPCを設置する（直線配線では100mの上限を超えるため、
   中継スイッチ／パッチパネルを間に設置する必要がある）
8. **案件08** — 会議室にWi-Fiアクセスポイントを設置し、無線で通信できるようにする
9. **案件09** — 建設課にワークステーションを導入する（通常のPCではなく、
   ワークステーションであることが要件）
10. **案件10** — 1台のスイッチに住民課・健康福祉課を収容しつつ、VLANで部署ごとに
    ネットワークを分離する（同じVLAN内は通信でき、別VLANとは通信できない状態を作る）
11. **案件11** — 会議室2にWi-Fi環境を整備する（コンクリート壁で電波が減衰する部屋のため、
    電波強度「中」以上を確保する必要がある）
12. **案件12** — L3スイッチを導入し、住民課（VLAN10）・健康福祉課（VLAN20）が、
    VLANで分離されたまま、それぞれ独立してインターネットに接続できるようにする
    （ルーターの空きポートを使うのではなく、L3スイッチのルーティングインターフェース
    ＝SVI経由で出られるようにする必要がある）

「🔍調査」モードでPCやサーバーを選ぶと、物理接続 → 電源 → ケーブル長 → ポート状態 → VLAN →
IP → サブネット → ゲートウェイ → ルーティング → NAT → DNS → インターネット到達、の
12段階を順番にチェックし、最初に失敗した段階とその理由を表示します（Pingツールも使えます）。
PC・サーバー以外の機器（スイッチ・ルーター・LANコンセントなど）を選ぶと、現場調査として
設置場所・電源状態・各ポートの接続先とケーブル情報を確認できます。
答えを一度に全部見せず、「なぜ繋がらないのか」を自分で突き止めるゲーム体験を狙っています。

「🔌配線」モードでは機器同士をタップしてケーブルを引けるほか、既存のケーブルをタップすると
切断できます。

スイッチの⚙設定画面では、VLANの登録（ID・名前）と、ポートごとのVLAN設定ができます。
各ポートはAccess（1つのVLANだけに所属）かTrunk（複数のVLANを1本のケーブルで通す）を
選べます。ポートのVLAN設定を間違えると、配線もポートも正常なのに特定の機器同士だけ
通信できない、という状態を作れます（🔍調査の診断で「VLAN」の段階が失敗として表示され、
原因を切り分けられます）。ルーター自体はVLANを理解しないため、ルーターの物理ポートに
直接つながるVLAN以外は、そのままではインターネットに出られません。複数のVLANをそれぞれ
インターネットに出したい場合は、L3スイッチを導入してVLANごとにルーティングインター
フェース（SVI）を設定します。SVIを持つVLAN同士は自動的に中継されるため、L3スイッチの
⚙設定でVLANごとのIPアドレス・DHCP・ルーターへのアップリンク先ゲートウェイを設定すると、
そのVLANのPCはL3スイッチ経由でインターネットに接続できるようになります（🔍調査の
「デフォルトゲートウェイ」「ルーティング」の段階で、L3スイッチ経由かどうかも確認できます）。

建物には壁の材質・床材を持つ部屋があります（ロビー＝ガラス、通信室・倉庫＝コンクリート
など）。Wi-Fiの電波強度はAPからの距離だけでなく、AP〜機器間の直線が通過する部屋の壁の
材質によっても弱くなります。特に会議室2はコンクリート壁のため、APを別の部屋に置くと
電波が大きく減衰し、圏外になることもあります。🔍調査の診断やPC・APの「情報」画面・
現場調査で、電波強度（圏外／弱／中／強）とどの部屋の壁を通過したかを確認できます。

ヘッダーの🎫ボタンから、ヘルプデスクを開けます。社員数・稼働PC/サーバー台数・未処理
チケット件数のダッシュボードと、届いたチケットの一覧を確認できます。チケットをタップ
すると、依頼した社員（部署・役職）と症状の詳細、原因の機器が分かります。「🔍現場で
確認する」から実際の🔍調査画面に移動して原因を突き止め、⚙設定で直したうえでチケットに
戻ると「対応完了にする」が押せるようになり、報酬を受け取れます（実際に直っていないと
押せません）。チケットは案件の進行に合わせて発生します。

機器の情報はどこからでも確認できます。ショップの各機器の「情報」ボタン、未配置の機器
（インベントリ）の情報ボタン、地図に置いた機器のタップ（または機器右上の小さな「i」ボタン）
のいずれからも、同じ「機器仕様」（価格・ポート・CPU/メモリなど、購入後も変わらないスペック）
を確認できます。設置済みの機器では、それに加えて「現在の状態」（電源・配線・IPアドレス・
通信状態など、今どうなっているか）も分けて表示されます。情報画面の「他の機器と比較」から、
複数の機種を選んで価格やスペックを横に並べて比較することもできます（ゲーム側からおすすめは
提示しません）。

ヘッダーの📖ボタンから、いつでも説明ブックを開けます。ネットワーク基礎・機器・配線・
ネットワーク設定・トラブル対応のカテゴリごとに、「①これは何？②現実では？③ゲームでは？
④構成例」の4項目で解説しています。多くのページには「🔧この画面で試してみる」ボタンがあり、
タップすると該当の操作モードにすぐ切り替わります。

## 技術構成

- Vite + TypeScript（フレームワークなしのシンプル構成）
- 機器・ポート・接続・部屋・案件・説明ブックはすべてデータとして管理
  （`src/devices.ts`, `src/rooms.ts`, `src/missions.ts`, `src/book.ts`, `src/types.ts`）
  しているため、将来の機器追加・案件追加・複数拠点などの拡張がしやすい構造になっています。
- `src/rules.ts` … 物理層の接続可否（有線ポート同士／無線ポート同士のみ）を判定
- `src/netutils.ts` … IPアドレス計算、L2ドメイン（ルーターを越えないLAN範囲）の特定、
  VLANを考慮したポート単位の到達性判定（`findVlanDomain` - ルーターだけでなくL3スイッチの
  ルーティングインターフェース＝SVI境界も検出する）、ルーターLAN・L3スイッチのVLAN
  インターフェースごとのDHCPアドレス割り当て、IP重複検出、最短経路探索
- `src/cables.ts` … ケーブル長の計算（マップ座標からメートル換算）と上限判定
- `src/diagnostics.ts` … 12段階の通信診断エンジンとPing機能
- `src/book.ts` … 説明ブックのカテゴリ・ページ内容
- `src/icons.ts` … 機器種別ごとの専用SVGアイコン（絵文字は不使用）
- `src/employees.ts` … 社員名簿（部署・役職）
- `src/tickets.ts` … ヘルプデスクのチケット生成・状態遷移・対応完了処理
- `src/wifi.ts` … 距離減衰と部屋の壁の材質を考慮したWi-Fi電波強度シミュレーション
- `src/building.ts` … 間取り図のベクター（SVG）データから抽出した本庁舎・別館の
  外形・壁データ（プレビュー専用、既存の部屋データとは別系統）

## 実装済み機能（v8.0 L3スイッチ）

- L3スイッチ（機種）を追加。既存のスイッチと同じくポートごとにAccess/Trunkの
  VLAN設定ができる上に、VLANごとにルーティングインターフェース（SVI：IPアドレス・
  サブネットマスク・DHCPの有無と範囲）を持てる。⚙設定画面でVLANの有効化・SVIの
  IP/DHCP設定・ルーターへのアップリンク先ゲートウェイを設定する
- VLAN対応の到達性判定（`findVlanDomain`）を拡張し、ルーターだけでなくL3スイッチの
  SVI境界も検出できるようにした。SVIを持たないVLANはこれまでどおりL2スイッチとして
  素通りし、SVIを持つVLANだけがそこでルーティングの対象になる
- 🔍調査の「デフォルトゲートウェイ」「ルーティング」の各段階がL3スイッチ経由の経路にも
  対応。ゲートウェイがルーターのIPかL3スイッチのSVIのIPかを判定し、ルーティング段階では
  L3スイッチのアップリンク先ゲートウェイが実際にルーターへ到達できるかを検証する
- DHCP・IP重複検出をルーターのLANだけでなく、L3スイッチのVLANインターフェースごとの
  スコープにも対応させた（`resolveAllConfigs`）
- Pingツールで、同じL3スイッチが中継する別VLAN宛のIPアドレスに対しても、
  インターネットに出ることなく成功と判定されるようにした（VLAN間ルーティング）
- 案件12：L3スイッチを使ってVLANごとに独立したインターネット接続を実現する案件を追加
- 📖説明ブックに「L3スイッチ」（機器）・「VLAN間ルーティング」（VLANカテゴリ）の
  ページを追加

  模様（タイルの格子・カーペットの斜線・OAフロアの細かい格子）をCSSで表現し、部屋ごとの
  見た目の違いを強めた

## 実装済み機能（v7.0 建物とWi-Fi）

- 建物の部屋を拡張（エントランス・営業部・総務部・通信室・開発部・会議室1・会議室2・倉庫）。
  各部屋は壁の材質（石膏ボード・木製壁・ガラス・コンクリート・厚いコンクリート）を持つ
- Wi-Fi電波強度シミュレーション：AP〜機器間の距離による減衰に加え、直線経路が通過する
  部屋ごとに、その部屋の壁の材質に応じた減衰を加算する（`src/wifi.ts`）。同じ部屋に
  居れば壁を通過しないため減衰は距離分のみ、別の部屋を経由すると壁の分だけ弱くなる
- 🔍調査の「ケーブル長」の段階を拡張：有線区間は従来どおり100m上限のケーブル長、
  無線（Wi-Fi）区間は電波強度が「圏外」になると失敗として扱い、通過した部屋名を
  含めて理由を表示する
- 機器の「情報」画面・現場調査（インスペクト）に、Wi-Fi接続機器の電波強度
  （圏外／弱／中／強とスコア）と通過した部屋を表示

## v8.0（L3スイッチ）の完成状況

設計書v6の§34開発順序は、Phase1-3（VLANの基本・Access/Trunk）の次にPhase4「L3スイッチ」・
Phase5「VLAN間ルーティング」を置いています。v6.0ではPhase1-3までに絞り、「L2/L3スイッチの
実質的な違いはVLAN間ルーティングができるかどうかにある」という理由でL3スイッチを見送って
いましたが、今回はそのPhase4-5に対応しました。

実装にあたっては、L3スイッチをVLANごとに独立した「ルーティングインターフェース
（SVI）」の集合として扱い、SVIを持つVLAN同士は静的なACL設定なしに自動的に中継される
（＝現実のL3スイッチと同じ挙動）という設計にしています。これにより、案件12は「VLANで
分離したまま」ではなく「L3スイッチ経由でそれぞれ独立してインターネットに出られる」ことを
要件にしています。同じL3スイッチにSVIを持つVLAN同士は、この時点で技術的には相互に
通信できる状態になるためです（これも現実のL3スイッチの正しい挙動で、それでも部署間の
通信を遮断したい場合はACLが必要になりますが、ACLは設計書v6自身がPhase4-5より後段に
置いている項目のため、今回は見送りました）。

L3スイッチのアップリンクは、この時点で1台しかいないルーターへの静的な1本に簡略化して
います。現実のL3スイッチが持つ本格的なルーティングテーブル（複数の宛先ネットワークへの
経路を個別に持つ）は、この対戦（ルーター1台・L3スイッチ0〜1台）では実質的に意味を
持たないため、「自分のSVIにないVLAN・ネットワーク宛はすべてこのアップリンク先へ」という
デフォルトルートのみの単純なモデルにとどめています。

## v8.2（建物の壁プレビュー）の完成状況

指示書§22の開発順序のPhase2「部屋の壁」に対応しました。Phase1で使ったベクターSVGを
そのまま流用し、外形と同じ抽出方法で、壁を構成するすべての部分パス（連続する部分
パス＝1つの壁や什器記号のまとまり）を取り出し、1つのSVGパス文字列にまとめています。

実装時に1点、変換ツール由来の問題に対応しました。間取り図の色塗り部分（2階の
議会事務局）を、面で塗りつぶす方式（fill-rule: evenodd）で描画すると、他の壁のような
「中空の二重線」ではなく単色の黒い塗りつぶしとして表示されてしまいました（色塗りが
壁の線と違う形でベクター化されたため）。この問題を個別に回避しようとする代わりに、
壁全体を塗りつぶさずストローク（線）だけで描く方式に変更しました。これにより、
議会事務局も他の部屋と同じ見た目の壁で表示されるようになり（指示していただいた
とおり、通常の部屋として扱われます）、かつ壁の太さも二重線として視覚的に分かる
ようになっています。

指示書§10が示す壁データモデル（`x1,y1,x2,y2,thickness`のような個別セグメント）は、
今回は採用していません。現時点ではまだ壁データをゲームロジック（Wi-Fi減衰・当たり
判定・部屋境界など）に使う予定がなく、このプレビュー画面はあくまで外形と壁の見た目が
実際の図面と一致しているかを確認するためのものだからです。壁データを実際のゲーム
システムに接続する段階（指示書§21のPhase 12「既存ITシステムとの接続」に相当）に
なったら、必要な形式（個別セグメントか、部屋単位の材質かなど）を改めて検討します。

## v8.1（建物外形プレビュー）の完成状況

新しい指示書「V7.1 村役場マップ再構築・実装指示書」は、絶対ルールとして「部屋の位置・
大きさを勝手に変更しない」「ユーザーの図面にない斜め線を勝手に追加しない」を掲げ、
§22の開発順序でPhase1「建物外形（本庁舎と別館）。間取り図と一致することを確認する」を
最初に置き、§23で「特にPhase1〜4では家具やIT機器を追加せず、まず建物そのものが正しいか
確認する」ことを明記しています。今回はこのPhase1のみに絞り、本庁舎（1F/2F）・別館の
外形を確認用のプレビュー画面（ヘッダーの🏛）として追加しました。指示書の要求どおり、
既存の部屋・機器・配線・ミッション・診断など、動いている仕組みには一切手を加えていません
（§24）。

外形データの取得方法は2段階ありました。最初は間取り図の画像を目視でトレースしましたが、
実際の図面と大きくずれてしまいました。そこでユーザーから、間取り図をベクター化ツールで
変換したSVGファイルを提供していただき、そちらを機械的にパースし直しています
（`src/building.ts`）。具体的には、SVG内の各`<path>`要素を解析して、壁線が構成する
連続した部分パス（continuous subpath）のうち、外壁の輪郭に対応するもの（バウンディング
ボックスの大きさから特定）の頂点列をそのまま座標として抽出しました。目視での読み取りを
挟まないため、建物外形・斜め壁の角度は元図面とほぼ正確に一致しています。本庁舎1階と
別館は、図面上でも渡り廊下の壁でひとつづきの外壁ラインとして描かれていたため、今回は
無理に分割せず、1つの多角形としてそのまま扱っています（Phase 2以降、部屋や壁を追加する
段階で渡り廊下の接続部を見直します）。
